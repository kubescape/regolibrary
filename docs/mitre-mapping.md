## Taxonomy and evidence rules

The target is Microsoft’s [Threat Matrix for Kubernetes](https://microsoft.github.io/Threat-Matrix-for-Kubernetes/), whose [About page](https://microsoft.github.io/Threat-Matrix-for-Kubernetes/about/) describes it as inspired by MITRE ATT&CK. It is distinct from the [MITRE ATT&CK Containers matrix](https://attack.mitre.org/matrices/enterprise/containers/). Keep the existing framework identity `MITRE`; update the description to name the Microsoft source accurately. The table copies Microsoft tactic placements and links only ATT&CK IDs explicitly present in each pinned technique page. Empty ATT&CK cells are intentional.

A mapping indicates a relevant existing check, not complete technique coverage or observed exploitation. **Weakness** inspects configuration/preconditions; **permission** identifies authorized actions; **inventory** requests human review; **support** checks a partial mitigation. Shared `microsoftMitreColumns`/rule taxonomy attributes remain unchanged. This document’s table is the reviewed technique mapping, including C-0054 → Discovery and the exclusion of registry allowlisting as private-image-theft protection. Framework membership itself has no per-technique association field, and this update adds none. C-0054 still carries only `Lateral movement` in shared runtime metadata, while C-0078 still carries `Collection`. The source-linked table records C-0054 under Discovery as well as Lateral Movement and C-0078 as Initial Access supply-chain support. Synchronizing shared runtime metadata is separate work.

### Remaining gaps

- Cloud-account MFA and cloud IAM credential retrieval; trusted-IP endpoint firewall effectiveness; dedicated per-pod cloud identities and effective pod IMDS isolation. Existing metadata evidence is node-level only.
- Arbitrary user kubeconfig confidentiality, generic static-pod manifest-directory ownership/write protection, and disabling web-hosted kubelet manifests. Named CIS file checks are narrower.
- Remote tamper-resistant container-log collection/storage, event retention integrity, and actual name-similarity detection. Audit-enabled and image allowlisting do not close these gaps.
- Complete controller/workload update/patch authorization, malicious sidecar/backdoor identification, checkpoint authorization, poisoned DNS/ARP traffic detection, runtime shell/miner/exploit activity, and ARP-resistant CNI proof.
- Image provenance signatures and general vulnerability coverage need additional fixture/configuration/live-provider evidence; digest pinning and known RCE correlation provide narrower support.
- Backup correctness, restore ability, numerical resource quota adequacy and network DDoS protection remain outside these checks.

## Known rule inaccuracies retained for separate repair

C-0058 and C-0059 are **unreliable heuristics**, retained provisionally at the maintainer's request. Age alone is not the reason for this qualification; direct evaluation exposes incorrect outcomes. Their shared definitions are unchanged.

| Control | Existing behavior and interpretation |
| --- | --- |
| C-0058 | Compares Kubernetes versions lexically rather than semantically. It flags patched `v1.20.11`, misses vulnerable `v1.19.9`, and inspects `subPath` but omits `subPathExpr`. The [official CVE-2021-25741 advisory](https://github.com/kubernetes/kubernetes/issues/104980) establishes the affected and fixed versions. This is not reliable general host-filesystem escape detection. |
| C-0059 | Misses unmitigated ingress-nginx `0.49.1` and `1.0.1`; either version still requires configuration mitigation. An unrelated ConfigMap in the same namespace with `allow-snippet-annotations: "false"` can incorrectly suppress the finding. The [official CVE-2021-25742 advisory](https://github.com/kubernetes/kubernetes/issues/126811) requires both a mitigation-capable version and the controller's mitigation setting. |
| C-0084 | `service_to_pod` compares label values without checking keys and requires only some matching values rather than every Service selector. A Service selecting `app=api` can match a Pod labelled `unrelated=api`; `app=api,tier=frontend` can match `app=api,tier=backend`. These are false exposure correlations. An external-facing Service, matching image vulnerability object, and `categories.isRce=true` remain prerequisites. |

### Reproduce the local full-framework selection smoke

Set `KUBESCAPE_BIN` to the checksum-verified v4.0.16 binary. This recipe writes temporary fixtures and exports only. The allow/disallow images are policy strings; no real registry or live image-scanner result is claimed. JSON documents are valid YAML inputs. Each RCE case uses a distinct namespace and matching image identifier to isolate the selector condition.

```bash
KUBESCAPE_BIN="${KUBESCAPE_BIN:-kubescape}"
"$KUBESCAPE_BIN" version
export MITRE_WORK
MITRE_WORK=$(mktemp -d /tmp/regolibrary-mitre.XXXXXX)
OUTPUT="$MITRE_WORK/export" RELEASE=mitre-288-local python3 scripts/export.py
jq '.settings.postureControlInputs | .imageRepositoryAllowList = ["allowed.example/"]' \
  "$MITRE_WORK/export/default_config_inputs.json" > "$MITRE_WORK/controls-config.json"
python3 - <<'PY'
import json, os
from pathlib import Path
work = Path(os.environ['MITRE_WORK']) / 'fixtures'
work.mkdir()
def pod(name, host=False, image='allowed.example/smoke:1', labels=None, namespace='smoke'):
    return {'apiVersion': 'v1', 'kind': 'Pod',
            'metadata': {'name': name, 'namespace': namespace, 'labels': labels or {'app': name}},
            'spec': {'hostPID': host, 'hostIPC': host, 'hostNetwork': host,
                     'containers': [{'name': 'app', 'image': image}]}}
def write(name, objects):
    (work / (name + '.yaml')).write_text('\n---\n'.join(json.dumps(o) for o in objects) + '\n')
write('host', [pod('host-enabled', True), pod('host-disabled')])
write('registry', [pod('registry-allowed'), pod('registry-disallowed', image='disallowed.example/smoke:1')])
write('admission', [{'apiVersion': 'v1', 'kind': 'Namespace',
    'metadata': {'name': 'psa-' + level, 'labels': {} if level == 'unlabelled' else
                 {'pod-security.kubernetes.io/enforce': level}}}
    for level in ['unlabelled', 'baseline', 'restricted']])
for name, rce, labels, selector in [
    ('rce', True, {'app': 'victim'}, {'app': 'victim'}),
    ('non-rce', False, {'app': 'victim'}, {'app': 'victim'}),
    ('mismatched-key', True, {'other': 'victim'}, {'app': 'victim'}),
    ('partial-selector', True, {'app': 'victim', 'tier': 'backend'}, {'app': 'victim', 'tier': 'frontend'})]:
    namespace, image = 'vuln-' + name, 'allowed.example/' + name + ':1'
    write(name, [pod(name, image=image, labels=labels, namespace=namespace),
        {'apiVersion': 'v1', 'kind': 'Service', 'metadata': {'name': name, 'namespace': namespace},
         'spec': {'type': 'NodePort', 'selector': selector,
                  'ports': [{'port': 80, 'targetPort': 80, 'nodePort': 30080}]}},
```
